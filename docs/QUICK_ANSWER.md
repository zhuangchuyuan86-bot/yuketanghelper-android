# 自动抢答

0.2.14 新增“设置 → 通用课程设置 → 自动抢答”，默认关闭。保存一次后，所有账号的已选课程共用；未选课程、未启用的账号不参与。

## 使用

1. 停止监测，使用同签名的 `YuketangHelper-Android-0.2.14-debug.apk` 覆盖安装，无需卸载或重新配置 AI。
2. 在课程页勾选课程并应用，进入“设置 → 通用课程设置”，勾选“自动抢答”并保存。
3. 回总览开始监测。收到老师发起抢答的消息后，助手按服务端倒计时等待，开放时自动参与。
4. 在消息页查看“抢答”记录。只有服务端明确返回成功时才显示“自动抢答成功”；此后请留意老师提问。抢答功能不调用 AI，不会代替你回答口头问题。

本机通知和语音提醒中可单独勾选“抢答”。更新保留原有通知类型选择；若旧配置未包含该类型，可自行勾选。首次体验也可用演示账号，约每 32 秒出现一轮模拟抢答，3 秒后给出演示结果，不访问真实课堂。

## 时序与结果

- 使用服务端 `start - now` 计算等待，手机系统时间不影响倒计时。等待最多 5 分钟，字段缺失或超出范围时提示到官方端查看。
- 抢答直接从课堂信号分发，不等待课件读取或 AI 推理。收到结束消息、下一轮替换当前轮或停止监测时，取消尚未发出的请求。
- 当前课堂重复推送和断线重连不会重复参与同一轮。重连中的 `hello.jumpinid` 会先查询当前信息；查询失败不会盲目提交。
- 每轮参与请求最多一次，不做自动网络重试或跳转重发。应用进程内的记录按账号、课堂和抢答轮次隔离，也保护修改设置引起的监测重启。进程结束后记录不会恢复；再次开启监测时可能重新参与仍开放的轮次。
- 超时或响应缺少确认时显示“未确认”，不显示成功，不再次提交；请在官方端核对。结束、未抢到和接口拒绝分别显示，诊断只保留固定文字与数字代码。

需要处于有效课堂连接和正常后台监测中。网络延迟、系统后台限制、旁听身份和服务端规则会影响结果，无法保证抢到。本版尚未进行真实课堂或手机实测。

## 接口核实

2026-10-29 读取官方公开学生端静态脚本，未使用真实账号或向真实课堂提交请求。这是前端行为核实，不是官方承诺稳定的开放 API 文档。

| 行为 | 公开学生端行为 |
| --- | --- |
| 发起消息 | `op: jumpinstart`，详情位于 `jumpin`，含 `id`、`now`、`start` |
| 结束消息 | `op: jumpinend` |
| 重连恢复 | `hello` 中的 `jumpinid`，随后查询当前抢答信息 |
| 查询 | `GET /api/v3/lesson/rapid-answer/get-info?id=…` |
| 参与 | `POST /api/v3/lesson/rapid-answer/participate`，JSON 仅携带原始类型的 `id` |
| 结果 | HTTP 成功、业务 `code=0` 后读取 `data.status`；1 成功、2 结束，其余整数按未抢到处理；缺失或异常状态保持未确认 |
